# NPC Hit Diagnostic 1.0.0

Отдельный диагностический GUI для ручного удара по NPC. Этот скрипт наблюдает исходящие
клиентские вызовы; не вызывает, не повторяет и не изменяет FireServer/InvokeServer сам.
Предыдущие скрипты репозитория не заменяются.

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/Probothotspot/Slap-battles-Teleport/main/NPC-Hit-Diagnostic.lua"))()
```

1. Запустить скрипт. Запись включена сразу. Наш отдельный NPC GeneralHit, если он сейчас
   работает на этом сервере, выключается, чтобы не мешать ручному тесту. Сам обратно не включается.
2. Ударить NPC обычной перчаткой вручную.
3. В окне посмотреть имя/класс/путь ивента, метод и аргументы. Стрелки выбирают запись.
4. Нажать **Копировать всё** и прислать отчёт. Копируются выбранная запись и JSON последних
   12 записей вместе с возможностями executor. При недоступном буфере весь текст выделяется
   в поле для ручного копирования.
5. Если записей нет, нажать **Поймать все Remote на 10 секунд**, сразу ударить NPC и
   снова скопировать. После десяти секунд возвращается обычный фильтр; запись не выключается.

## Что записывается

- Фактическое имя, ClassName, полный GetFullName и Lua-выражение пути к объекту ивента.
- FireServer либо InvokeServer, реальное число аргументов (включая nil).
- Типы/значения аргументов, в том числе таблицы, Vector2/Vector3/CFrame/Color3/EnumItem.
- Для Instance: полный путь, выражение с корректным `["Right Arm"]`, родитель, класс,
  принадлежность Workspace; для части тела также позиция, размеры, CanTouch/CanCollide,
  Anchored, Transparency.
- Модель NPC, Humanoid, здоровье, тип рига и дистанция от локального персонажа, если определимы.
  Модели в Workspace.Enemies без Humanoid отмечаются как **предположительный** NPC.
- Локальный персонаж, позиция/здоровье, текущий Tool и leaderstats.Glove, если они доступны.
- Инициирующий скрипт через getcallingscript и доступный debug.traceback. Недоступные
  сведения явно помечаются как неизвестные; имя скрипта не выдумывается.
- Executor/версия, доступность API, установленные перехватчики, ошибки установки, PlaceId/JobId,
  время, пропущенные записи и признаки обрезки.

CallPreview — текстовое представление обнаруженного вызова, а не автоматически выполненный
повтор. При неполном снимке или неподдерживаемых значениях повторяемый код не формируется.
Даже успешная запись вызова не доказывает, что сервер принял удар или нанёс урон.
Ответ InvokeServer не записывается: оригинальный вызов продолжается без наблюдения за ответом.

## Перехват и ограничения

Основной путь — hookmetamethod + getnamecallmethod для вызовов через `:`. Если они не
установились, пробуется hookfunction для FireServer/InvokeServer. Работа конкретного
перехватчика зависит от executor; наличие имён API ещё не доказывает его работоспособность.
В окне отдельно указаны «hook установлен, ожидается реальный вызов» и реальные записи.
Для прямых вызовов сохранённой функции без `:` основной __namecall-перехват может не сработать.
Если API отсутствуют, GUI всё равно появляется и позволяет скопировать отчёт возможностей.
В таком случае сам факт наличия GeneralHit в игре не заменяет отсутствующий перехват.

Обычный фильтр сохраняет вызовы с NPC-Instance в аргументах либо с Hit/Slap/Attack/Damage
в имени ивента. Совпадение только по имени помечается как неподтверждённое NPC-событие.
Короткий режим «все Remote» нужен для неизвестных имён/числовых ID. Вызовы скриптов executor
игнорируются, если checkcaller доступен; иначе источник отмечается как unknown.

Лимиты: последние 12 записей; 20 снимков/с с начальным запасом на 8 вызовов одного удара;
до 16 аргументов, 180 узлов/3 мс на снимок, 5 уровней вложенности и 30 элементов таблицы.
Длинные строки/стеки обрезаются с отметкой; бинарные строки выводятся в hex. Полный снимок
произвольного пакета не гарантируется: Truncated/Dropped и явные причины показывают ограничения.

Повторный запуск использует тот же собственный dispatcher, чтобы не наслаивать перехватчики.
OFF/закрытие отключают слушатель. После закрытия остаётся небольшой пересылающий dispatcher,
а не попытка вслепую восстановить __namecall поверх чужого нового перехватчика. Оригинальные
аргументы/результаты/nil/ошибки не подменяются. Закрытие удаляет GUI/обработчики/анимации;
при смене сервера старый слушатель не записывает вызовы нового контекста.

Отчёт остаётся локально до нажатия копирования и ничего не загружается в сеть.

## Проверка

`lua NPC-Hit-Diagnostic-tests.lua` (Lua 5.4): 112 проверок снимков, путей, nil,
таблиц/циклов/обрезки, фильтров/пакетных вызовов, исходного возврата/ошибки/yield,
повторного использования и запасного перехвата, настоящего кода GUI, буфера,
отсутствующих API и очистки подписок. Живые Slap Battles/Xeno/Delta здесь не запускались.
