# Halloween Deep Inspector 1.0.0

Инспектор с деревом объектов, поиском по клиентскому коду и данным для подготовки
Halloween-фарма. Это отдельный файл в Slap-battles-Teleport. Старый тестер наблюдал
UI/значения/события; новый также ищет определения, таблицы и формулы в доступном
клиентском коде. Полный пользовательский отчёт для оценки прежних результатов
не предоставлялся; отсутствие полезных данных в нём не утверждается.

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/Probothotspot/Slap-battles-Teleport/main/Halloween-Deep-Inspector.lua?v=1.0.0"))()
```

## Использование

1. Запустить в нужном режиме. Обход и поиск кода стартуют автоматически, GUI
   появляется до окончания обхода. Следить за числами «код», «доступен», «закрыт»
   и числом незавершённых задач поиска фрагментов в сводке.
2. Если доступных исходников мало, нажать **Память: искать**. При наличии API
   проверяются живые функции известных игровых скриптов, их константы и upvalues.
   Неизвестные таблицы из getgc не выдаются за конфигурацию игры.
3. Нажать **Копировать находки** и прислать результат. Копируется приоритетный
   отчёт с кодом/таблицами/константами, важными значениями, API и примерами ошибок.
   **Полный отчёт** дополнительно содержит широкий каталог скриптов, ValueBase,
   Remote и прежние снимки/историю состояния. Он может быть значительно больше.
4. Для аргументов двери/accept candy включить **RPC: ещё 30 секунд** и выполнить
   действие вручную. Статический код и константы не заменяют наблюдение вызова.
5. Поле поиска принимает слова через запятую, например `capacity,backpack,maxcandy`
   или часть пути/ключа. Фильтр применяется к уже собранным находкам и не ограничивает
   первоначальное чтение скриптов. Совпадение хотя бы одного слова достаточно.

Тестер выключает наши запущенные Lantern AutoHit / NPC GeneralHit и закрывает
предыдущее окно Farm Diagnostic / NPC Hit Diagnostic. Автоатаки после закрытия
самостоятельно не включаются. События и изменения состояния продолжают писаться
при выключенном RPC. При отсутствии clipboard текст выделяется и остаётся
закреплённым в поле; выйти из него можно кнопкой Дерево или новой меткой состояния.

## Дерево как в инспекторе объектов

**Дерево** открывает Workspace; строки — реальные дочерние объекты.
Нажатие строки переходит внутрь, **↑** — к родителю, **< / >** — страницы.
Наверху показаны путь, доступные атрибуты/значения/свойства выбранного объекта.
Перейдя до DataModel, можно вручную просмотреть доступные сервисы. Наличие сервиса
ServerStorage/ServerScriptService в дереве не означает доступ к его серверным данным.

Выбор LocalScript/ModuleScript повышает его приоритет чтения, при необходимости
даёт одну дополнительную попытку. В дереве показан статус исходника/ошибка.
Свойства не редактируются, объекты не удаляются. В меню одного узла показываются
первые 600 детей, по 24 на страницу. Ограничение относится к ручному меню;
фоновый обход отдельно проходит доступную иерархию в своих пределах.

## Чтение кода и данных

- **Структура:** Workspace, ReplicatedStorage, ReplicatedFirst, локальный Player
  с PlayerScripts/PlayerGui/Backpack, StarterPlayer/StarterGui, когда доступны.
  Собственный GUI, ветки чата и анимационные KeyframeSequence/Pose пропускаются.
- **Атрибуты:** при обходе проверяются ключи всех объектов, до 40 полей на объект,
  а не только объектов с подходящим названием. Это покрывает часть пробелов
  предыдущего поиска по именам.
- **ValueBase:** сохраняются доступные значения, до 2000. Тематические пути/значения
  попадают в ранжированные находки; остальные остаются в полном отчёте.
- **Source:** пробуется свойство Source. В обычном клиенте оно обычно защищено;
  доступность определяется Roblox и executor.
- **Декомпиляция:** если Source закрыт и API decompile доступен, пробуется вывод
  этого API. Он отмечается как `Executor decompile output`, а не как оригинальный
  серверный исходник. Наличие API не доказывает корректную реконструкцию кода.
- **Loaded modules:** getloadedmodules используется только для перечисления.
  Модули не require-ятся и не запускаются. Модули из CoreGui/внешних корней
  исключаются; у detached-модулей явно отмечено неподтверждённое происхождение.
- **Функции скрипта:** getscriptclosure/getscriptfunction при наличии возвращают
  функцию для чтения getconstants/getupvalues (включая поддерживаемые debug-варианты).
  Функция не вызывается, неизвестный игровой код не исполняется.
- **Живая память:** отдельная кнопка вызывает getgc(true), затем ищет функции,
  у которых getfenv(fn).script совпадает с уже найденным игровым скриптом внутри
  известных игровых корней. Только их константы/upvalues анализируются.
  Произвольная таблица `Capacity=...` без связи с игровым скриптом игнорируется.
- **Таблицы:** raw next, до 3 уровней, 40 ключей на таблицу / 180 элементов на
  обход. Числовые ключи сохраняются в пути: например `[BagCapacity][2] = 3000`.
  Циклы не обходятся повторно. Метаметоды таблиц не используются.
- **Код:** по словам capacity/maxcarry/baglimit/backpack/candy/round/limit и др.
  выбираются строки с контекстом и номером. FireServer/InvokeServer также ищутся.
  Полные исходники в отчёт не включаются, только найденные фрагменты.

Результат всегда содержит путь, тип свидетельства, контекст/ключ, происхождение
и относительное время CollectedAfter. Разные категории отделяют код, константы,
таблицы, реплицированные значения и фактически наблюдавшиеся RPC.

Например, `RoundGoal=3000`, число `3000` среди констант и
`BagCapacity[2]=3000` — разные сведения. Даже последняя таблица является клиентским
свидетельством: сервер может использовать другие правила, ветку или режим.
Не создаётся выдуманное поле «точный лимит рюкзака». Комментарии/неиспользуемые
ветки/старый код могут совпасть с поиском. Рейтинг — эвристика для просмотра.

## Нагрузка и ограничения

Это не доступ к файлам сервера или диску Roblox. Если вместимость хранится только
на сервере и не отправляется клиенту, инспектор её не прочитает. Обфускация,
неподдерживаемые API, отключённый Source и стриминг могут ограничить результат.
Не проверенные на сервере лимиты/аргументы не объявляются установленными.

Обход: до 256 шагов / мягкий бюджет 1,5 мс за Heartbeat. Поиск по тексту/таблицам
также идёт порциями до 80 шагов / 1,5 мс. Каталог — до 10000 объектов, 1200 скриптов,
600 Remote, 2000 ValueBase, 350 лучших находок. Переполнение отмечается в отчёте.
Одновременно читается один скрипт; сначала тематические пути. По умолчанию до
256 попыток исходников и 24 вызовов декомпиляции. **Ещё код: +256** увеличивает
бюджеты на 256 скриптов / 24 декомпиляции, не перезапуская все закрытые скрипты.

На скрипт: первые 384 КиБ, 8000 строк, до 1600 байт строки, 30 найденных контекстов;
длинный/минифицированный код может обрезаться с SourceTruncated. Константы — до
96 скалярных значений функции. Память — до 50000 элементов getgc / 200 функций.
Поиск в памяти можно запустить снова для обновления значений, пока общий бюджет
функций не исчерпан. UI-снимки/RPC наследуют ограничения предыдущего Farm Diagnostic.

Ожидание Source/decompile/closure API ограничено 12 секундами с отбрасыванием
позднего результата и попыткой task.cancel. После таймаута последующие вызовы
декомпилятора/получения script closure отключаются до перезапуска. Уже прочитанный
исходник сохраняется, если зависла следующая стадия introspection.
Native API/getgc/GetChildren/JSON нельзя жёстко прервать посреди вызова; абсолютное
отсутствие зависаний конкретного executor не гарантируется. Несколько API и работа
обхода/прошлого мониторинга имеют отдельные мягкие бюджеты.

Собственных HTTP-запросов для анализа и отправки отчётов нет. Реализация executor
decompile может использовать свои внешние сервисы — это определяется executor.
Закрытие отключает свои обработчики, очередь и слушатель RPC; маленький общий
пересылающий dispatcher остаётся для переиспользования. Старый Farm Diagnostic
и Lantern AutoHit в репозитории не заменяются.

## Верификация

`lua Halloween-Deep-Inspector-tests.lua` — модельные проверки Source/decompile
с ошибками доступа, контекстов вызовов, таблиц с ключами раундов/циклами,
констант, getloadedmodules без require, getgc с привязкой к игровому скрипту,
ранжирования/лимитов, реального GUI и дерева, RPC/состояний, clipboard и очистки.
Неизвестная функция теста специально выбрасывает ошибку при выполнении и не
вызывается во время анализа. Живые Slap Battles/Delta/Xeno здесь не запускались.

Справочник Roblox: https://create.roblox.com/docs/reference/engine/classes/ModuleScript
и https://create.roblox.com/docs/reference/engine/classes/LuaSourceContainer .
Executor API не являются стандартными API Roblox; их поддержка проверяется на месте.
